# NodeSheet 改进建议

2026-10-19 对全代码库做的性能与用户体验审查结果。每条带文件位置、问题、量级、建议改法。按优先级分为：先做的五件 / 性能 / 用户体验。

## 先做的五件（投入产出比最高）

1. **Tab 无条件打开节点搜索**（UX#9）：现在 Tab 只在 `focus-area == 2`（画布有焦点）时生效，用户打开文件后最后点的是表格，按 Tab 没反应。表格是只读的、没有输入框，放开没有代价。`ui/app-window.slint` 的 `key-scope`。
2. **表格内查找 Ctrl+F**（UX#1）：见下"用户体验 1"。
3. **表头加排序三角 + 排序状态指示**（UX#3）。
4. **必填参数打星号 + 运行失败自动选中出错节点**（UX#11、#13）：错误反馈闭环。
5. **快捷键一览 / 快速上手帮助窗**（UX#8、#16）：复用 `ui/help.slint` 的现成结构，F1 无选中节点时打开，首次启动自动弹。

性能侧同档优先：**嵌套列表的 formatter 复用**（性能#3，秒级卡顿）和**连线 Path 包围盒**（性能#8，画布平移每帧 10~50 ms），都是小改动大收益。

## 一、性能（按影响从大到小）

### P0

**1. `category_index()` 按节点重复调用，每次重建 500 类型的排序表**
`src/panel.rs:130`（`push_graph` 里每个节点一次）→ `src/nodes.rs:749` → `categories()` 每次克隆 466 个生成的表达式类型 + 约 60 个精选类型、建 8 个 String、sort_by 全表，全程在 UI 线程。`push_graph` 有 30+ 处调用（选中、拖动、运行完成、改参数、撤销……）。20 个节点时单次多花 200~600 µs，拖动时每帧都在付。
**改法**：`NodeType` 加 `cat_index: i32` 字段，`NodeType::parse()` 末尾算一次；或加 `OnceLock<HashMap<&'static str, usize>>` 缓存。3 行改动。

**2. `push_kinds` 每次进网络都重建 466 项 KindItem 模型**
`src/panel.rs:781-801`：克隆 466 个 Arc + 排序 + 各建 `KindItem`，约 1~3 ms。只在注册表变化（`nodes::install/remove`）时才需要重建。
**改法**：加 `kinds_dirty` 标志，或只在需要全量列表时才建。

**3. `write_list`/`write_map` 每格每元素新建 `ArrayFormatter` + `FormatOptions`（灾难级）**
`src/loader.rs:1557-1665`：嵌套列表每格建 1 个 + 每个元素（最多 LIST_SHOWN=10 个）再各建 1 个 = 11 个 formatter/格。group_by 预览那种"每格几十万元素的列表"列，50 万行 ≈ 550 万次构造，**5~25 秒**。
**改法**：`cell_format()` 提成 `OnceLock<FormatOptions<'static>>`；formatter 按列类型在 `read_group` 外层建一次复用（`loader.rs:1756` 已有先例）。

### P1

**4. 每次 `engine::parse` 都序列化完整 466 项类型表**
`src/convert.rs:9-19` 的 `expr_types()` 每次重建 `{类型名: [[参数名, 类型, 是否端口]…]}`，约 60~100 KB JSON，Rust 构建 + Python `json.loads` 合计 3~5 ms/次。
**改法**：缓存成 `OnceLock<SharedString>`，`install`/`remove` 时置脏。

**5. 每次运行重复序列化整个 steps 树（含大参数），Python 侧再 dumps 一次算 key**
`src/engine.rs:560-587` 的 `step_json` 每参数发 `[kind, value, label, default]` 四元组，`label`/`default` 是静态的却每次重发。`create` 的 `read_clipboard` 粘贴 10 万行后：10 MB 文本在 Rust 侧 JSON 转义一次、`engine.py:1388` 的 `key_of` 又 `json.dumps` 一次，每次运行 50~110 ms。
**改法**：Rust 侧算好每个 step 的内容哈希传给 Python 当缓存 key；`label`/`default` 只在注册表变化时发一次；请求里只留 `[kind, value]`。

**6. CSV 打开时全文件扫描建 `Vec<u64>` offsets**
`src/loader.rs:1474-1493`：256 MB 文件 ≈ 1.3 秒全扫；5000 万行 → offsets 占 400 MB，且 `Vec::new()` 从零反复 2× 扩容。
**改法**：偏移 < 4 GB 用 `u32`（内存减半）；`with_capacity(file_size / 平均行长)`；超大文件只索引前 N 行、后面按需顺序扫（稀疏索引 + 锚点）。

**7. 表格每格最多 9 次跨 FFI 回调**
`ui/table-panel.slint:512-567`：每格 1 次 `cell-selected` + 4 次 `in-primary` + 4 次 `cell-extra-*`，600 可见格 ≈ 5400 次 FFI/帧（1~5 ms），滚动时 `idx` 变化全部重调。
**改法**：4 个 `cell-extra-*` 合成一个返回位掩码的 `cell-extra-edges(idx, i) -> int`（5 行改动，省 3/4）；进一步把加选块判断搬进 Rust 侧模型。

**8. 每根连线是一个覆盖整个画布的 Path**
`ui/node-panel.slint:1213-1230`：20 根线 = 20 个全画布大小的 Path item，平移时（pan-x/y 变）每帧 20 次 `wire-path` 字符串生成 + 20 个全画布 Path 重新光栅化，**10~50 ms/帧**，是画布平移卡顿的直接原因。
**改法**：Path 的 x/y/width/height 设成连线包围盒（加 padding），viewbox 同步；或所有连线合成一个 Path。

**9. `make_row` 每行 VecModel + N 个 `StandardListViewItem`；行缓存超限整体清空**
`src/view.rs:54-96`：64 行块 × 20 列 = 1280 次 SharedString 分配 + 64 个 VecModel（0.5~2 ms/块）；`ROW_CACHE_LIMIT = 8192` 超限 `cache.clear()` 整体清空，回滚时缓存全丢（缓存抖动）。
**改法**：`ROW_CACHE_LIMIT` 提到 65536 或改 LRU；`ROW_BLOCK` 64 → 256/512（块边界抖动频率降 4~8 倍）；`StandardListViewItem` 若只是 `text` 包装就换成 `SharedString`。

**10. 列宽自适应：500 行 × n_cols 两次遍历 + 每格 String 分配**
`src/view.rs:140-157`：换表时 1~5 ms。
**改法**：两遍合一（一遍同时算最大 `visual_width` 和数值比例）；`sample` 借 `Chunk` 的紧凑存储不分配；`visual_width` 提前退出。

### P2

**11. `col-at` 每次鼠标移动做 `get_columns()` + N 次 `row_data` 克隆**
`src/main.rs:430-441`：拖选时 2000 次 `ColumnSpec` 克隆/秒。列宽在 `App.col_widths` 里已有，直接读它。

**12. `RecParser::emit` 每行 2 个 Vec 分配**
`src/loader.rs:1340-1369`：千万行 CSV ≈ 2000 万个 Vec 分配（1~3 秒）。提成 `RecParser` 字段，每次 `clear()` 复用容量。3 行改动。

**13. `push_graph` 全量重建 NodeItem；`summary()` 每次重算；拖动每帧调**
`src/panel.rs:118-151,1508` + `src/graph.rs:301`：`summary()` 遍历参数、解析 conditions JSON。`summary()` 按 `(node_id, params_hash)` 缓存；拖动路径只更新 x/y（`push_positions` 已做对）。

**14. 每个数值格一次 `DISPLAY.read()` RwLock**
`src/loader.rs:346,422,1525,1530`：500 万格 ≈ 175 ms。解码批开始处读一次 `DisplayFmt` clone 传下去。

**15. `par_iter` 对 1 个块也走 rayon 调度**
`src/loader.rs:1055`：`if raw.len() == 1 { 直接 parse } else { par_iter }`。

**16. `XLSX_CHUNK_ROWS = 100_000` 使 `xlsx_append` 持锁片段长**
`src/loader.rs:1033-1041`：可调小到 50_000 让 UI 更新更平滑（首屏延迟略降）。

### P3

**17. 网格 72 个 Rectangle item，平移时全重算**（`ui/node-panel.slint:1122-1131`）：合成一个绘制 item，~1 ms/帧。
**18. calamine 兜底路径每格 `get_value().clone()`**（`src/loader.rs:983`）：换成 `examples/bench_xlsx.rs:139-145` 的 optimized 写法（直接 match `DataRef`）。
**19. `depends_on` 递归 + 线性 `node()` 查找无 memo**（`src/graph.rs:1253`）：O(V×E)，节点图 <100 时无所谓。
**20. parquet 结果写盘再读回**：`decode_group` 是整组解码，复制（`selection_text`）和列宽取样踩到时会为 64 行解码整组 100 万行。给 `decode_group` 加行数上限或让 `GroupCache` 记住部分解码状态。

## 二、用户体验（按用户痛感从强到弱）

### Excel/WPS 用户的高频动作缺失（痛感最强）

**1. 表格里没有 Ctrl+F 查找——完全缺失**
Excel/WPS 用户打开表格的第一个反射动作。现在找一行数据要建五个节点，且 `str.contains` 只能匹配一列。CLAUDE.md 的红线是"数据操作在节点图"，但 UI 层"定位到下一个命中格"不违反它。
**改法**：Ctrl+F 在表格面板弹搜索条（回车/箭头跳上下处，命中格描边高亮）；匹配在 `LazyRowsModel` 缓存之上做（已解码行直接比对，未解码按块 `scan`），不动数据层；搜索框加"建筛选节点"按钮（复用 `quick.rs::value_test`，加 `Contains` 变体）；右键菜单加"在表里查找…"。

**2. 没有跳到行 / Ctrl+G**
100 万行的表想看第 50 万行只能拖滚动条。`LazyRowsModel` 已支持任意行 `scan`。
**改法**：Ctrl+G 弹"跳到行"（接受 `1234` 或 `R1234C5`）；或把 Ctrl+F 框做成 Excel 式"名称框 + 查找"合一（数字 = 跳行，文字 = 查找）。Slint 侧设 ListView `viewport.y`。

**3. 表头没有排序/筛选的可视入口，也没有排序指示**
点列名只是选中，排序藏在右键菜单里，可发现性为零。
**改法**：列头 hover 淡显 8px 三角（点一下升序、再点降序、第三次取消，或中键）；不要把左键点列名改成排序（会破坏选整列）。显示排序结果时在路径栏写"按城市升序"。加 hover 提示"点：选中列 · 右键：排序/筛选/统计"。

**4. 不能冻结列**
横向滚到第 40 列时看不到第一列的名字。首行冻结其实已有（表头不动），但用户不知道。
**改法**：最小版——`TablePanel` 加 `freeze-cols: int`，冻结列像左上角 `#` 块一样不随 `content-x` 移动；表头右键加"冻结到这列 / 取消冻结"。

**5. 行高不可调、字号没有数字输入**
行高 = 字号 + 15px 写死（`app-window.slint:126`）；改字号连带按比例改所有列宽（`view.rs::zoom_table`）。
**改法**：`row-h` 拆出 `row-pad`，设置里加"行高：紧凑/标准/宽松"三档；"表格缩放"勾选式菜单项改成字号面板（9~28px + 预设），加"只改字号不改列宽"选项。

**6. 右键菜单（ctx-card）缺的三项**
现有菜单做得很好（表头 5 项 + 格子 2 项 + 通用 3 项，整列多选自动变），缺：
- "复制"不说明复制的是哪块——加一行灰字"复制的是：第 3 行 × B:D"；
- 没有"复制这一格的值（不带 CSV 引号）"——`selection.rs::push_cell` 会给含制表符/引号的文字加引号；
- 行号列右键没有"只留这些行"；
- 筛选只有"等于/不等于"——加"**筛选这列…**"，打开 `CondPick` 预填这一列等于该值（复用条件编辑器，成本很低，把精确等于升级成完整筛选）。

**7. 复制只有 TSV 一种格式**
**改法**：ctx-card 的"复制"加小箭头弹"复制为：表格(制表符) / CSV / Markdown 表 / HTML"，约 30 行。或往剪贴板多写一份 HTML 格式。

### 新用户上手（痛感第二强）

**8. 第一次打开没有引导、示例、欢迎页；F1 空转**
空状态做得不错（图标、格式徽章、打开按钮），但打开文件后看到一个 read 节点就不知道该干什么了；F1 只给"选中节点的帮助"，没选中时什么也不会发生。
**改法**（按性价比）：复用 `help.slint` 做"快速上手 + 快捷键一览"浮层，F1 无选中节点时打开，首次启动自动弹（`settings.json` 加 `first_run` 标记）；空状态加"打开示例数据"按钮和三步引导图文。

**9. Tab 只在画布有焦点时生效** —— 见"先做的五件"第 1 条。另外：空查询列出全部 400+ 节点是劝退的墙，应改成列"常用"（每分类取 3~5 个，限 20 条 + "输入以搜索全部"）；搜索结果加分类徽章。

**10. 节点图对新手太 Houdini 化**
双击进网络是最难的操作，而筛选/排序/分组/加列全都必需；group_by 三张网络吓退新手。
**改法**：右键表头升级成新手主入口（文案写人话，加"筛选这列…"和"按这列分组汇总…"）；表格路径栏加常驻"快速筛选条"；expr 的上下文下拉改成中文（加列/筛选行/分组聚合/排序）+ 切换提示；group_by 默认只显示"聚合"页签，分组键/筛选组折叠成次要页签。

### 错误反馈（痛感第三）

**11. 必填参数在表单里零标示**
`ParamDef.required` 存在但 `ParamItem` 没这个字段，只能按 F5 失败才知道。
**改法**：`ParamItem` 加 `required: bool`，必填且为空时标签前加 `*`（填了就不标）；节点头加"未填必填：N"徽章。

**12. 参数填错不指出哪个参数、不能跳转**
现在只是一个红块字符串。
**改法**：`engine.py` 的 `convert` 失败回报结构化错误（param 下标 + 原因），红块旁加"选中这个参数"按钮；列名/dtype 这类可静态判断的在 Rust 侧推参数时当场校验；Python traceback 折叠进"详细信息"而不是丢掉。

**13. 状态栏红点不可点；失败不自动选中出错节点**
**改法**：红点可点，打开"问题"浮层列出所有出错节点 + 原因，点一条选中对应节点；`node_failed` 里加 `graph.select_only(Some(id))`（一行改动）；状态栏文字改成带错误摘要。

**14. 文件打不开只显示状态栏一行字；"不支持的格式"列表是错的**
`LoadError::Unsupported` 里手写的短列表**漏了 json/ndjson/arrow/feather/ipc/arrows/avro/rtv**——这些实际支持（走引擎读），是误导性错误信息。
**改法**：打不开文件弹窗；格式列表动态从 `read` 节点的 `extensions` 生成（`files.rs::engine_reads` 已有先例）。

**15. 参数面板底部的代码预览对新手是噪音**
**改法**：默认折叠成"看代码"小按钮；非 code 节点默认不显示（同时省回 28px 参数区高度）。

### 键盘可达性

**16. 没有应用内快捷键一览** —— 见"先做的五件"第 5 条。菜单"重做"只写了 Ctrl+Y，补上 Ctrl+Shift+Z；状态栏提示行做成"点一下打开快捷键一览"。

**17. 表格里按 Delete 无反应无提示**：可接受（表格只读），低优先级——状态栏短暂闪"焦点在节点图上"。

**18. 输入框里 Ctrl+Z 撤销的是文字**：符合直觉，低优先级。

### 渐进解码 / 大文件

**19. 解码中没有总量、没有用时、不能取消**
"已 12,340 行"停住不动会被当成卡死；打开 3GB xlsx 想取消只能关窗口。
**改法**：解码循环检查 `Arc<AtomicBool>`，`DataSource` 加 `cancel()`，状态栏文字可点取消；显示已用时间（"已解码 12,340 行 · 1.2 秒"）；xlsx 的 `<dimension>` 不可信但可以只用来做"约 N 行"的显示。

**20. 大 CSV mmap 锁文件，界面无提示**
>256MB 的 CSV 内存映射后别的程序改不了，手册里有 FAQ 但界面没有提示。
**改法**：打开 mmap 文件时状态栏常驻一行淡字提示（极小改动）。

### 节点图易用性

**21. 没有小地图 / 节点大纲，找不到显示节点**
**改法**（性价比从高到低）：表格路径栏的显示节点名做成可点（点了选中画布上那个节点，<20 行）；节点图面板加"节点"页签列当前级所有节点（名字+状态，点击选中）；右下角迷你总览图；`G` 无选中时自动选显示节点。

**22. 没有节点历史前进**：加"最近浏览层级"栈，Backspace 回刚才那层。低优先级。

**23. 静止时端口几乎不可见**（4px 高）：hover 或无选中时端口常显 6px 小圆点。

### 参数面板

**24. 隐藏参数突然消失、填的值被当默认值丢掉**
切"方式"后用不到的参数直接消失，`Graph::compile` 按默认值传给代码。用户填的"1d"就这么没了（切回来还在 `node.params` 里，但用户不知道）。
**改法**：隐藏的参数变灰只读显示而不是消失（`push_params` 不过滤、传 `visible` 标志）；或表单底部显示"当前方式用不到 6 个参数，内容已保留，点查看"。

**25. 参数没有"恢复默认值"**：参数行右侧加只在 `value != default` 时出现的"↺"按钮（参照 fmt 对话框已有的"恢复默认"）。

**26. 参数列表滚动位置切节点时重置；无参数搜索**：记 ScrollView 的 viewport.y；参数多的节点（read 22 个）加参数名搜索框。

**27. "选列"按钮和手写框的关系不明**：按钮 hover 提示写明"手写的选择器也认；点这个可视化地选，会替换框里的内容"。

### 工程文件 / 最近打开

**28. 未保存弹窗标题不带文件名**：标题改成 `未保存 · <文件名>`（表格文件打开时正文也没提是哪个文件）。

**29. 保存失败只塞状态栏**：保存失败弹窗；默认保存路径（数据文件旁边）不可写时建议改存 `%USERPROFILE%`。

**30. 没有自动保存 / 崩溃恢复**
花 10 分钟搭的图，崩了全没。`.rtv` 很小，自动保存成本几乎为零。
**改法**：图变了去抖 3 秒后把 `Graph::to_json()` 写进 `%APPDATA%\nodesheet\session.json`，下次启动问"上次有一份没保存的节点图，要打开吗？"。

**31. 最近打开没有"清除"、不能钉住**：加"清除最近打开"菜单项；确认超长文件名在 MenuEntry 里是否 elide（潜在排版 bug）。

### 显示设置与个性化

**32. 列宽不按文件记忆**
精心拖了 30 列宽度，关掉重开全没了（`reset_sheet_view` 清空，`.rtv` 的 `ui_state` 也不存）。
**改法**：按列名（不是下标）存进 `settings.json` 的 `col_widths: {文件路径: {列名: 宽度}}`，LRU 淘汰；`refresh_view` 算完自适应后优先用记录；`ui_state` 里也存一份跟工程走。

**33. 主题默认深色对 Excel/WPS 用户反直觉**：默认改跟随系统（0）。

### 其他摩擦点

**34. "从剪贴板建表"埋了五层**（添加菜单 → 创建 → create → 切方式 → 点按钮）：空状态和"文件"菜单加直接入口"从剪贴板建表"；快捷键 Ctrl+Shift+V。

**35. Ctrl+E 关掉节点面板后没有找回入口**：表格路径栏右下角加"◨ 显示节点面板"小按钮。

**36. 取消选中时参数面板塌成 0，画布跳一下**：没选中时面板显示"未选中节点"占位而不是塌成 0。

**37. 状态栏 file-meta 与 stats 混排易误读**（"xlsx · 2.4 MB · 1,000 行"里前者讲原文件后者讲结果表）：显示节点结果时 file-meta 加"原文件"前缀或隐藏。
